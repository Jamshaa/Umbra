# Pixel team playbook — Umbra

> **For the Boss:** this is your mission book. Wave 1 tasks (§4) come with an
> EXACT payload, ready for `create_task`. You derive the rest (§5) with the
> same discipline, reading `docs/PLAN.md`
> (F01–F20 matrix) and `docs/ARCHITECTURE.md` before slicing.
> **For workers:** run YOUR task to the letter; the repo hard rules are in
> `AGENTS.md` (root): git, secrets, Windows env, style.

---

## 1. Canonical goal (phrase it like this)

> Working local Umbra Kubernetes operator: detects the 20
> injected faults (F01–F20 in `docs/PLAN.md`), diagnoses with LLM via tool
> calling, applies the patch in an isolated sandbox, verifies deterministically
> without AI, and only on green verification proposes the fix for explicit
> human approval; snapshot rollback with no residue on failure.

Done means: from a fresh `kind` cluster, the repo's
injectors + harness reproduce the scoreboard table (Day 5)
with no undocumented manual step.

**Hard gates:**
- **Day 3:** ≥ 1 fault healed end-to-end (detected → sandbox-verified →
  proposed to production). If not: stop, fix the integration — not the idea.
- **Day 5:** ≥ 12/20 on the scoreboard. Below: cut the set to the top-10 and
  present THAT. Zero inflation.

## 2. How you operate (role reminder + repo quirks)

1. `list_board` before every decision: priorities, dependencies and real
   blockers, not assumed ones.
2. **Little WIP**: 1–2 active workers max; review as soon as they deliver.
3. Atomic `create_task`: one concern per task; observable acceptance
   (command, file, behavior); `files[]` given; `blockedBy` with the
   REAL ids the tool returns.
4. `spawn_worker` from unblocked backlog by priority (P0/P1 first).
5. Review: check the diff against criteria one by one. If
   inconclusive, CONCRETE amendment note (file:line + what's missing).
6. `request_approval` when closing each **wave** (not per task): 3-part
   summary (what / why / how verified). **Merging to the
   main tree is a human action** after approval — never
   force it or take it for granted.
7. On `CONCURRENCY`/`NOT_RUNNABLE`: wait, reorder, retry later.
   Never retry loops.
8. To the human chat: 3–6 lines, concrete ids, real snapshot state.
9. These missions ADD to your role prompt and `AGENTS.md`: nothing here
   loosens what's forbidden there.

## 3. Repo laws that are NOT negotiable (summary)

- Workers: commit ONLY on their `task/<id>` branch in THEIR worktree; **never push,
  never PRs, never commits to `main` nor the boot branch**; human
  integration after approval. `AGENTS.md` §1 rules.
- Secrets: zero private material (`SECURITY.md` §3/§4); placeholders always
  (`example.com`, `<REPLACE-ME>`, fake `demo` namespaces); the local kubeconfig
  has contexts alien to Umbra: absolutely forbidden.
- Env: Windows; binaries by absolute path (stale PATH; paths in
  `AGENTS.md` §3); `make` and `kustomize` don't exist → `kubectl apply -k`;
  Kubebuilder CLI doesn't exist → manual scaffold + CRDs via
  `go run sigs.k8s.io/controller-tools/cmd/controller-gen@v0.19.0`.
- Every matrix fault F ships ALWAYS with its three artifacts together:
  injector + deterministic verifier + row already in `docs/PLAN.md`.
- Verification is deterministic and NEVER uses AI, ever.
- Everything going to a Finding's `status` passes first through the evidence
  sanitizer (`internal/evidence`, built in Wave 1).

## 6. If something gets stuck

- `blocked` worker: read the reason. Missing context → ATOMIC `res` task.
  Task that turns out to be two → split and relaunch. Failures outside the worker →
  `requeue_task` with a surgical note (what and why).
- Zero "wait & retry" loops: if after 2 rounds there's no new data, escalate
  to the human chat with evidence and options to decide.
- Quality rules: a badly defined task returns debt. Better 1 GATE task
  green than 5 half tasks.
- Day 3 and Day 5 gates always go to the human with `request_approval`
  and evidence: that's the wave's peak moment.
